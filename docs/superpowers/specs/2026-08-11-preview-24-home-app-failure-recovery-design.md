# Preview 24：首页应用接管失败恢复设计

## 背景

首页应用入口由家属配置，老人反复点击完成视频、相册、天气等任务。当前 `HomeAppLauncher` 在解析不到包或 `startActivity` 抛出异常时会正确释放 1.2 秒防重复点击闸门，但 `HomeNavigator` 只显示一条短 Toast：

```text
无法打开<应用名>
```

Toast 会在老人读完前消失，也没有告诉老人下一步该做什么。入口可能只是暂时失败，也可能已经被停用或卸载；自动移除入口会破坏家属的配置意图。

## 目标

- 让老人明确知道“这一次没有打开”，并在当前页面看到可执行的下一步。
- 保留一次明确的“再试一次”，复用现有启动闸门和失败释放逻辑。
- 为家属提供直达银杏“家属设置”的入口，以检查或移除失效首页应用。
- 成功启动路径的调用次数、延时和动画行为保持不变。
- 不增加后台任务、定时器、服务、Root 命令或 BusyBox 依赖。

## 非目标

- 不验证外部应用是否真正到达前台；Android/ColorOS 不提供一个对所有第三方应用可靠且无副作用的同步确认。`startActivity` 成功仍表示本地交接成功，不在本版宣称外部应用已可用。
- 不自动删除、禁用或重排失效入口。
- 不处理来电、微信自动点击或联系人数据库错误；这些保留给后续独立版本。

## 方案比较

### 方案 A：继续 Toast

实现成本最低，但老人无法在读完后找到错误，也没有恢复动作。不能满足失败可恢复目标，放弃。

### 方案 B：持久对话框（选定）

失败后展示大字号对话框，标题显示应用名，正文说明可能被停用/卸载，并提供“再试一次”和“家属设置”。重试沿用同一个 `HomeAppLauncher`，失败闸门已经释放；再次失败时替换为新的同类对话框。对话框由 Activity 管理，按返回键或取消可回到首页。该方案只改变失败分支，成功路径零额外工作，能在 Robolectric 中完整验证。

### 方案 C：首页内嵌错误横幅

需要把一次性失败事件接入 `MainActivity`/Header 状态和 RecyclerView 生命周期，横幅还可能挤压老人当前首页内容。它比对话框更容易被忽略，且为一次性错误引入持久状态，暂不采用。

## 交互契约

1. `HomeAppLauncher` 解析或启动失败，调用 `HomeNavigator` 的失败处理。
2. 失败处理先关闭当前同类对话框，再展示 `dialog_home_app_failure`；不显示异常堆栈、包名或技术术语。
3. “再试一次”关闭对话框后调用同一个 `HomeAppLauncher.open(item)`。成功则离开银杏；失败则再次展示对话框。
4. “家属设置”关闭对话框并打开 `SettingsActivity`，让家属进入现有首页应用管理入口。
5. 对话框使用现有老年版 Dialog 样式；两个操作均为整行大目标（至少 `68dp` 高），有可读文本和 `contentDescription`。不增加隐藏长按或坐标点击。按返回键或点对话框外部可回到首页。
6. `HomeNavigator.dismissTransientDialogs()` 在 Activity 销毁时清理引用；若 Activity 已结束，失败回调直接忽略。

## 验收与验证

- Robolectric：失败显示对话框、应用名和两项动作；点击“家属设置”启动 `SettingsActivity`；解析/启动失败后立即重试仍可调用启动器；成功启动不显示对话框。
- 现有 `HomeAppLauncherTest` 全部保持通过，特别是失败后闸门立即释放。
- 布局测试：按钮高度、文本和无障碍描述存在，长应用名不越界（标题最多两行并尾部省略）。
- 性能/功耗：成功分支不新增同步查询、延时、动画、协程或服务；失败分支只创建一个前台对话框，关闭后无持久任务。
- 设备证据：Preview 24 不虚报 OnePlus 15/ColorOS 16 的外部应用前台成功率；安装到目标机后由用户验证停用/卸载/冷启动场景。
