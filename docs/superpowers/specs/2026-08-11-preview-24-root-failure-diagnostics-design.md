# Preview 24：Root 失败精确诊断设计

## 背景

银杏当前只在家属主动打开 Root 专机面板时执行一次固定状态脚本。旧实现把 `su` 无法启动、
KernelSU 拒绝、模块脚本缺失、命令超时、非零退出和状态格式错误全部折叠成“Root 不可用”。
这个状态没有排障价值，也会让真机反馈无法定位到 Root 入口、授权、模块还是协议层。

## 目标

- 保留现有一次显式 `su -c <固定脚本>` 调用，不增加探测命令、轮询、服务或后台任务。
- 在徽章中显示短原因，在摘要中显示观察到的事实、必要的 UID/退出码和下一步。
- 区分进程启动、Root 授权/脚本执行、超时/输出、状态协议四层失败。
- 修复动作失败时也显示该动作本身的原因，而不是只显示修复后的健康快照。
- 不把无法从应用侧证明的推断伪装成确定结论。

## KernelSU 边界

目标机固定为一加 15、中国版 ColorOS 16、KernelSU。KernelSU 官方源码在
[`sucompat.c`](https://github.com/tiann/KernelSU/blob/243f0dd161b4899e57f2072c0f8597fef245a396/kernel/feature/sucompat.c)
中把兼容入口定义为 `/system/bin/su`，并且只对 allowlist 中的当前 UID 接管该路径的
`faccessat`、`stat` 和 `execve`。因此：

- 银杏改为直接执行 `/system/bin/su -c <固定脚本>`，避免依赖应用进程的 `PATH`。
- 未授权 UID 与系统确实没有该入口，都可能在应用侧表现为 `ENOENT`。银杏不能仅凭这一结果
  断言“肯定未授权”；UI 显示“当前 UID N 找不到 `/system/bin/su`”，并明确提示 KernelSU
  未授权该 UID 时也会出现此结果。
- 只有进程输出明确包含拒绝授权语义时，才显示“未授权”。若输出不足以判断，则显示原退出码
  和“无法进一步判定”，不猜测根因。

## 分类契约

1. `ProcessBuilder.start()` 阶段：区分入口不存在、入口存在但执行被系统阻止、其他启动失败。
2. 进程阶段：优先识别超时和输出超限；再区分明确授权拒绝、Root Guard 路径权限拒绝、
   脚本/依赖缺失和普通非零退出。普通失败保留退出码。
3. 协议阶段：命令退出 0 但状态字段缺失、重复或取值非法时显示“状态格式异常”。
4. 有效状态：`module=missing` 继续显示“模块未安装”；`DEGRADED` 与 `HEALTHY` 的既有规则不变。
5. 原始标准输出和异常文本只在内存中按既有 16 KiB 上限处理，不直接展示给老人，也不写入
   新日志或上传网络。

## UI 与功耗

- Root 卡片徽章使用“su 入口不可见”“未授权”“缺少脚本”“脚本被阻止”“检查超时”等短文案。
- 卡片摘要和 Root 面板状态行显示可执行的家属处理步骤；修复失败 Toast 使用长时长显示同一原因。
- 普通打开设置页仍不触发 `su`；只有主动进入 Root 面板或点击修复才执行既有固定入口。
- 不新增 `id`、KernelSU 探针、BusyBox 检查、定时任务、唤醒锁、网络请求或 Root 模块资产。

## 验收

- 单元测试覆盖入口不存在、不可执行、明确授权拒绝、脚本权限拒绝、脚本缺失、超时、输出超限、
  普通退出码和格式错误。
- Repository 保留失败原因与退出码；修复动作失败后仍会读取一次最新状态，并单独保留动作原因。
- Robolectric 验证所有原因都有具体摘要、`su` 不可见摘要包含当前 UID、授权失败徽章不再显示
  “Root 不可用”。
- 完整测试、APK 构建和 lint 分类在发布前重新强制执行；没有连接目标机时不宣称 KernelSU
  真机结果。
