# 银杏 Root 保活预览 1

首个 Root 专机预览版，目标设备为中国版一加 15、ColorOS 16、KernelSU。该版本先验证保活底座和无障碍自动恢复，不调整微信自动化流程和老人桌面布局。

## 资产

- `yinxing-1.10.0-root-preview.1-debug.apk`：Debug 签名体验 APK。
- `yinxing-guard-1.10.0-root-preview.1.zip`：KernelSU 模块。
- `SHA256SUMS.txt`：两个文件的 SHA-256 校验值。

## 安装前注意

这个 APK 使用当前构建机的 Debug 签名，不是正式发布私钥签名。若手机上的银杏使用了其他签名，Android 会拒绝覆盖安装。卸载旧版会删除该应用的本地联系人和设置，请先确认数据已经备份，再决定是否清洁安装此预览版。

首版固定 Android 用户 0，不支持工作资料、系统分身或其他多用户空间。

## 安装顺序

1. 安装 `yinxing-1.10.0-root-preview.1-debug.apk`，至少启动一次，并将银杏设为默认桌面。
2. 打开 KernelSU 管理器，从本地安装 `yinxing-guard-1.10.0-root-preview.1.zip`。
3. 确认模块 `Yinxing Root Guard` 已启用。
4. 重启手机。
5. 等待系统进入桌面；模块会在开机完成后修复银杏包状态、无障碍服务、Doze 白名单和可用的后台 app-op，然后只以 60 秒间隔检查状态。

模块不会在每次检查时强行切回银杏首页。它只在本次开机首次成功修复后打开首页；如果当时应用尚未安装好或首页启动失败，则每 60 秒重试，成功后不再抢占前台。手动点击 KernelSU 模块的“操作”按钮也会执行一次修复并打开首页。

## 体验检查

1. 重启后无需进入 Android 无障碍设置，确认银杏已回到默认桌面。
2. 打开系统无障碍列表，确认银杏服务已启用。
3. 如果原本启用了 TalkBack 或其他无障碍服务，确认它们仍然保留。
4. 手动关闭银杏无障碍服务，等待最多 60 秒，再确认服务恢复。
5. 强行停止银杏，等待 60 秒后按 Home，确认桌面仍可使用；守护模块不会在使用微信时强制抢占前台。
6. 在 KernelSU 管理器中点击模块“操作”，确认它执行一次修复并打开银杏首页。
7. 禁用模块并重启，确认银杏仍按原有非 Root 模式运行。
8. 如要测试完整卸载，重新启用模块并重启后再卸载模块；下一次开机完成时确认 `/data/adb/boot-completed.d/yinxing-guard-uninstall-cleanup.sh` 已自动消失。

## 诊断

模块日志标签固定为 `YinxingGuard`，每条记录包含模块版本和固定动作名。可通过已授权的终端查看：

```sh
su -c 'logcat -d -s YinxingGuard'
```

反馈问题时请提供一加 15 的 ColorOS 完整版本、KernelSU 管理器/内核版本、复现步骤和上述日志。日志设计不记录联系人、电话号码、令牌或微信界面内容；提交前仍请检查并移除个人信息。

## 回滚

1. 在 KernelSU 管理器中禁用或卸载 `Yinxing Root Guard`。
2. 重启手机，使后台守护进程确定停止。
3. KernelSU 会在 Android 服务尚未启动的早期阶段删除模块，因此卸载钩子不会阻塞开机等待 DeviceIdle。模块运行期间已经保留一个惰性的固定清理助手；守护循环会在助手缺失或目标类型错误时重试安装，卸载钩子会原子刷新它，刷新失败也不会删除旧助手。模块目录消失后，助手在开机完成时撤销由模块添加的 Doze 白名单，成功后自动删除自己；如果系统服务暂时失败或所有权标记损坏，脚本和标记会保留到下次开机重试。
4. 清理不会主动关闭银杏，也不会删除系统无障碍列表中的银杏或其他服务。如需完全恢复手动授权模式，可在 Android 无障碍设置中手动关闭银杏服务。

若需要手动确认或完成 Doze 清理，可在已授权终端执行：

```sh
su -c 'cmd deviceidle whitelist -com.yinxing.launcher'
```

如果手机无法正常进入系统，请使用 KernelSU 的模块救援方式禁用 `yinxing_guard`，再重启。该预览不修改 `/system`、不增加 SELinux 规则，也不安装通用 Root 命令接口。

## 本地验证边界

发布前会执行宿主 Shell 与 KernelSU 同类 `ASH_STANDALONE=1` BusyBox 行为测试、并发锁/失败注入测试、可复现 ZIP 结构与权限测试、Android JVM 测试和 Debug APK 构建。构建机没有连接目标一加 15，因此 ColorOS 16 的开机、无障碍重新绑定和厂商后台策略必须以本次真机体验结果为准。
